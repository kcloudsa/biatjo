# Auth API

Base URL: `http://localhost:3001/auth`

This module provides the authentication layer for the Byatjo API. It handles registration, email verification, login, token refresh, password reset, session management, and Google OAuth.

## Authentication model

- Access tokens are JWTs generated by `generateAccessToken(...)`.
- Refresh tokens are stored server-side and returned as a secure `refreshToken` cookie.
- Protected routes use Passport JWT middleware via `authenticateJWT(passport)`.
- Session-based login is enabled for local and Google login flows.
- Successful responses usually use this shape:

```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": "user_123",
      "email": "user@example.com",
      "name": "Ahmed",
      "role": "user"
    },
    "token": "eyJhbGciOi...",
    "accessToken": "eyJhbGciOi..."
  }
}
```

## Routes

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| POST | `/auth/register` | No | Create a standard user account |
| POST | `/auth/registerDriver` | No | Create a driver profile after a user exists |
| POST | `/auth/otp/register` | No | Send a verification OTP for a registered email |
| POST | `/auth/otp/resend` | No | Resend an email verification OTP to an existing, unverified user |
| POST | `/auth/otp/verify` | No | Verify a one-time password |
| POST | `/auth/forgot-password` | No | Request password reset flow |
| POST | `/auth/password-reset/check-otp` | No | Check a password-reset OTP without changing the password |
| POST | `/auth/reset-password` | No | Reset password using existing flow |
| POST | `/auth/password-reset/request` | No | Request a reset token |
| POST | `/auth/password-reset/validate` | No | Validate a reset token |
| POST | `/auth/password-reset/complete` | No | Complete password reset |
| POST | `/auth/login` | No | Authenticate a user with email/password |
| POST | `/auth/login/dash` | No | Restrict dashboard login to admins/superadmins |
| POST | `/auth/refresh` | No | Refresh JWT using the refresh cookie |
| POST | `/auth/logout` | No | Delete session, clear cookies, revoke refresh token |
| GET | `/auth/me` | JWT | Return the authenticated user's profile |
| GET | `/auth/google` | No | Start Google OAuth |
| GET | `/auth/google/callback` | No | Handle Google OAuth callback |

## Environment variables

The app expects values such as:

```bash
PORT=3001
DB_URI=mongodb://localhost:27017/byatjo
JWT_SECRET=your_jwt_secret
ACCESS_TOKEN_SECRET=your_access_secret
REFRESH_TOKEN_SECRET=your_refresh_secret
SESSION_SECRET=your_session_secret
AUTH_GOOGLE_ID=your_google_client_id
AUTH_GOOGLE_SECRET=your_google_client_secret
FRONTEND_URL=http://localhost:5173
EMAIL_USER=your.address@gmail.com
EMAIL_PASS=your_gmail_app_password
BREVO_API_KEY=xkeysib-your_brevo_key
```

For local development, store these in a root `.env` file. For production on Railway and the email provider setup, see [docs/email.md](../email.md).

```bash
npm install

```

## Basic usage examples

### 1) Register a user

```bash
curl -X POST http://localhost:3001/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "userName": {
      "firstName": "Ahmed",
      "lastName": "Elasmar"
    },
    "contactInfo": {
      "email": {
        "email": "ahmed@example.com"
      },
      "phone": {
        "phoneNumber": "+218912345678"
      }
    },
    "password": "StrongPassword123!",
    "userInfo": {
      "gender": "male",
      "nationality": "Libya"
    }
  }'
```

Example response:

```json
{
  "success": true,
  "message": "User created successfully. Please check your email for a verification code.",
  "data": {
    "userId": "U123456",
    "email": "ahmed@example.com",
    "displayName": "A.",
    "verified": false,
    "expiresAt": "2026-11-02T09:40:00.000Z",
    "verifyEndpoint": "/auth/otp/verify"
  }
}
```

Registration does **not** return tokens. The user is signed in after verifying the email code (see below).

The email-only flow resends the verification code for an existing, unverified account (same as `/auth/otp/resend`):

```bash
curl -X POST http://localhost:3001/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "emailOnly": true,
    "email": "ahmed@example.com"
  }'
```

If registration created the account but email delivery failed, resend the verification code:

```bash
curl -X POST https://your-api-url/auth/otp/resend \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com"
  }'
```

Successful response:

```json
{
  "success": true,
  "message": "Verification code sent. Please check your email.",
  "data": {
    "expiresAt": "2026-11-02T09:40:00.000Z"
  }
}
```

Then verify the code:

```bash
curl -X POST http://localhost:3001/auth/otp/verify \
  -H "Content-Type: application/json" \
  -d '{ "email": "ahmed@example.com", "otp": "123456" }'
```

A successful verification signs the user in. It sets the `refreshToken` cookie and returns:

```json
{
  "success": true,
  "message": "Email verified successfully",
  "data": {
    "verified": true,
    "userId": "U123456",
    "email": "ahmed@example.com",
    "displayName": "Ahmed E.",
    "role": "user",
    "token": "access-token-value",
    "accessToken": "access-token-value",
    "refreshToken": "refresh-token-value"
  }
}
```

Codes expire after 10 minutes, and only the most recently sent code works. `/auth/otp/register` remains available for compatibility and performs the same resend action. Emails are matched without regard to letter case.

See [Email verification rules](../email.md#email-verification-rules) for every action that checks or sets verification.

### 2) Log in

```bash
curl -X POST http://localhost:3001/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com",
    "password": "StrongPassword123!"
  }'
```

Example response:

```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": "U123456",
      "email": "ahmed@example.com",
      "name": "Ahmed",
      "role": "user"
    },
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

If the password is correct but the email is not verified, login returns `403` and a new code is emailed when the previous one has expired:

```json
{
  "success": false,
  "message": "Email is not verified. Enter the code sent to your email, or request a new one.",
  "error": "EMAIL_NOT_VERIFIED",
  "data": {
    "email": "ahmed@example.com",
    "verifyEndpoint": "/auth/otp/verify",
    "resendEndpoint": "/auth/otp/resend"
  }
}
```

A wrong password always returns `401 INVALID_CREDENTIALS`, whether or not the email is verified.

### 3) Use the access token

After login or email verification, send the token in the `Authorization` header:

```bash
curl http://localhost:3001/auth/me \
  -H "Authorization: Bearer <ACCESS_TOKEN>"
```

Example response:

```json
{
  "success": true,
  "message": "User data retrieved",
  "data": {
    "user": {
      "id": "U123456",
      "email": "ahmed@example.com",
      "role": "user"
    }
  }
}
```

### 4) Refresh an access token

The refresh token is stored in a cookie named `refreshToken` and can also be returned in the response body.

```bash
curl -X POST http://localhost:3001/auth/refresh \
  -H "Cookie: refreshToken=<REFRESH_TOKEN>"
```

Example response:

```json
{
  "success": true,
  "message": "Token refreshed successfully",
  "data": {
    "accessToken": "new-access-token"
  }
}
```

### 5) Log out

```bash
curl -X POST http://localhost:3001/auth/logout \
  -H "Content-Type: application/json" \
  -d '{
    "refreshToken": "<REFRESH_TOKEN>"
  }'
```

The endpoint clears the auth cookies and destroys the session.

### 6) Forgot password with OTP

Request a verification OTP:

```bash
curl -X POST http://localhost:3001/auth/forgot-password \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com"
  }'
```

Example response:

```json
{
  "success": true,
  "message": "Password reset code sent. Please check your email.",
  "data": {
    "expiresAt": "2026-11-02T09:40:00.000Z"
  }
}
```

Use the OTP to set a new password:

```bash
curl -X POST http://localhost:3001/auth/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com",
    "otp": "123456",
    "newPassword": "NewSecurePassword123!"
  }'
```

Optionally check the OTP before submitting the new password:

```bash
curl -X POST http://localhost:3001/auth/password-reset/check-otp \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com",
    "otp": "123456"
  }'
```

Successful check response:

```json
{
  "success": true,
  "message": "Reset code is valid"
}
```

The check does not consume the OTP. Submit the same code to `/auth/reset-password` to complete the reset. Invalid/expired checks count toward the five-attempt limit; after five attempts, requests are locked for 15 minutes.

Example response:

```json
{
  "success": true,
  "message": "Password has been reset successfully."
}
```

The project also includes the link-based reset flow below as a backup/alternative:

```bash
curl -X POST http://localhost:3001/auth/password-reset/request \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com"
  }'
```

Then validate the reset token:

```bash
curl -X POST http://localhost:3001/auth/password-reset/validate \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com",
    "token": "reset-token-from-email"
  }'
```

Finally, complete the reset:

```bash
curl -X POST http://localhost:3001/auth/password-reset/complete \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ahmed@example.com",
    "token": "reset-token-from-email",
    "newPassword": "NewSecurePassword123!"
  }'
```

### 7) Google OAuth

To start Google sign-in:

```bash
curl -L http://localhost:3001/auth/google
```

This redirects the browser to Google. After the login flow completes, the callback redirects back to the frontend configured in `FRONTEND_URL` with a token in the query string.

## Frontend usage example

```js
const response = await fetch('http://localhost:3001/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    email: 'ahmed@example.com',
    password: 'StrongPassword123!'
  })
});

const payload = await response.json();

if (payload.success) {
  const token = payload.data.token;

  const profile = await fetch('http://localhost:3001/auth/me', {
    headers: {
      Authorization: `Bearer ${token}`
    }
  });

  console.log(await profile.json());
}
```

## Error handling

Common error responses include:

```json
{
  "success": false,
  "message": "Email is required",
  "error": "EMAIL_REQUIRED"
}
```

Typical codes include:

- `VALIDATION_ERROR`
- `EMAIL_EXISTS`
- `PHONE_EXISTS`
- `INVALID_CREDENTIALS`
- `TOKEN_EXPIRED`
- `INVALID_REFRESH_TOKEN`
- `USER_NOT_FOUND`
- `OAUTH_NOT_CONFIGURED`

## Notes

- `POST /auth/register` creates a user and immediately returns an access token + refresh token.
- `refreshToken` is typically used from browser cookies, but it can also be passed manually in a request body.
- Dashboard access is restricted to `admin` and `superadmin` roles via `/auth/login/dash`.
- Google OAuth only works when the Google Passport strategy is configured in environment variables.
